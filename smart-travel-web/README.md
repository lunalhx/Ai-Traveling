# Smart Travel Web (数字文旅教育平台 Web 演示端)

## 1. 前端项目定位
本项目为基于 Java Spring Boot 后端的配套 Vue 3 Web 演示端。当前工程为**基础架构版本**，已完成脚手架搭建、核心依赖安装、请求拦截与路由守卫等底层机制的封装，**暂未实现具体的业务页面与真实接口联调**，仅提供了基础 UI 占位模板，旨在为后续业务的快速填充提供标准化的开发环境。

## 2. 技术栈
* **核心框架**: Vue 3 (Composition API)
* **构建工具**: Vite
* **UI 组件库**: Element Plus
* **路由管理**: Vue Router
* **网络请求**: Axios

## 3. 目录结构说明
```text
smart-travel-web/
├── .env.development       # 开发环境全局变量配置
├── vite.config.js         # Vite 核心配置（含反向代理设置）
├── src/
│   ├── api/               # 后端接口方法定义（按业务模块如 user, spot 分类）
│   ├── assets/            # 静态资源
│   ├── components/        # 全局复用的 UI 组件（如侧边栏 AppSidebar、顶栏 AppHeader）
│   ├── layout/            # 页面整体布局骨架（MainLayout）
│   ├── router/            # 路由表映射及全局鉴权守卫配置
│   ├── utils/             # 全局工具类函数（如 request.js, auth.js）
│   ├── views/             # 具体的业务视图组件（当前大多为占位状态）
│   ├── App.vue            # Vue 应用程序根组件
│   ├── main.js            # 入口执行文件
│   └── style.css          # 全局样式重置与设定
```

## 4. 环境变量说明
项目中通过 `.env.development` 统一管理开发环境的环境变量：
* `VITE_API_BASE_URL=/api`：指定了全站 Axios 网络请求的统一前缀，也是触发 Vite 本地跨域代理机制的关键标识。

## 5. 本地启动方式
确保你的计算机已安装了 Node.js 环境。
```bash
# 进入前端项目目录
cd smart-travel-web

# 安装全部依赖包
npm install

# 启动本地开发服务器
npm run dev
```

## 6. 后端代理配置说明
为解决前后端分离开发过程中的跨域问题，并在代码中隐藏真实的后端物理地址，本项目在 `vite.config.js` 中配置了代理服务器：
* 所有请求路径只要以 `/api` 开头，都会被 Vite 代理层拦截。
* 代理层会自动将请求转发到后端的实际运行地址（默认配置为 `http://localhost:8080`）。
* 在转发过程中，`/api` 前缀会被动态剥离（例如前端发起 `/api/user/me`，后端实际收到的是 `/user/me`）。若后端端口改变，只需修改 Vite 配置文件中的 `target` 属性。

## 7. 路由说明
项目采用动态嵌套路由架构：
* **免登录区**: `/login`（完全独立的全屏页面）。
* **核心业务区**: 基于 `/` 的嵌套路由（如 `/dashboard`, `/spots` 等）。这些页面共享 `MainLayout` 提供的主界面（左侧菜单 + 顶部导航条）。
* **全局路由守卫**: 在 `router/index.js` 中设置了 `beforeEach` 拦截器。它强制要求访问业务页面的用户必须持有本地 Token，否则会强行阻断并跳转到登录页；反之，已登录用户访问登录页也会被强行引导至首页大盘。

## 8. Token 处理说明
* **存储方式**: 用户登录凭证（Token）安全保存在浏览器的 `localStorage` 中。
* **统一收口**: 所有关于 Token 的读写和清除逻辑完全封装在 `src/utils/auth.js` 中，杜绝在业务页面散落直接调用原生缓存机制的代码。
* **无感注入**: `src/utils/request.js` 中配置了请求拦截器。前端在调用任何接口前，系统会自动获取 Token 并挂载到请求头的 `Authorization` 字段。
* **失效处理**: 响应拦截器统一监听 `401` 状态码。一旦服务端判定授权过期，前端会自动销毁本地缓存并弹回登录页面，无需在各处捕获异常。

## 9. 后续业务页面开发计划
当前前端工程的地基已经稳固，下一步可以直接基于现有的占位文件开展业务开发。规划清单如下：
* **登录页完善**: 联调真实短信发送接口与登录鉴权，获取真实 Token。
* **首页大盘**: 获取并展示用户信息。
* **景点模块**: 构建瀑布流或列表视图展示景点数据，支持多维度筛选。
* **打卡签到**: 对接前端 LBS 定位权限验证，调用后端 GPS 范围合法性判定。
* **秒杀抢购**: 设计异步订单轮询进度条与防超卖、防连点的前端限流交互。
* **订单历史**: 设计状态切换的 Tab 页与基础订单详情展示。
* **后台管理工具**: 对接缓存预热相关的管理端独立接口。
